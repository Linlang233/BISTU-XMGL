# 软件项目管理实验总结报告

## 一、项目组织情况

本项目采用四人协作模式完成，团队成员分别承担项目管理、计划制定、配置管理以及冲突处理等职责。

项目整体采用 Git 进行版本控制，并基于分支协作模式完成项目文档开发与整合。

\---

## 二、WBS分解思路

本项目采用交付物导向方式进行WBS分解，围绕项目管理文档、活动管理模块、报名管理模块、签到管理模块以及配置管理模块进行三级分解。

通过WBS分解，项目任务结构更加清晰，便于后续进度安排与任务分配。

\---

## 三、进度安排依据

项目进度计划主要依据以下原则制定：

* 优先完成项目基础结构；
* 按照文档依赖关系安排任务顺序；
* 保证关键路径任务优先完成；
* 明确每项任务责任人。

项目整体周期为7天，共划分为项目初始化、文档编写、配置管理、冲突测试以及总结验收五个阶段。

\---

## 四、配置管理过程

项目采用 Git 作为版本控制工具，并建立 main、dev 以及 feature 分支。

团队成员基于 feature 分支完成个人任务开发，完成后统一合并至 dev 分支，最终由项目经理合并至 main 分支。

通过配置管理机制，项目实现了版本可追溯、协作过程规范化以及文档统一管理。

\---

## 五、冲突制造与解决过程

实验过程中，小组成员分别在不同 feature 分支中修改 docs/06-conflict.md 文件中的相同内容，成功制造 Git 冲突。

Git 自动识别冲突后，在文件中生成冲突标记：

```text
<<<<<<< HEAD
=======
>>>>>>> feature
```

团队成员通过手工修改方式保留正确内容，并删除冲突标记，随后重新提交修复版本，最终成功完成分支合并。

\---
